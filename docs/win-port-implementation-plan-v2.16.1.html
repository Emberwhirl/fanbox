1 · Decisions you are most likely to tweak

Each card states the default I will implement unless you say otherwise. Everything here is user-facing. A change is recorded as a deviation in the live log.

D1 · In-app update on Windows: keep the download flow, no electron-updater auto-install decided

Upstream 2.16 made the update capsule fully automatic on macOS (electron-updater downloads a zip, then swaps the app on restart). That mechanism can only discover updates through a latest.yml asset on the release. You asked for releases without the yml, so the Windows capsule keeps today's flow for both installer and portable users: 下载更新 downloads the exact installer to Downloads and opens it; the user clicks through. Upstream's updater code stays in the tree but is inert on Windows (the probe returns false without a network round-trip, and an error listener is registered so a stray updater error cannot crash the main process).

D2 · Agent status now comes from Claude Code itself (hooks), not from reading the terminal

Since 2.15, upstream asks Claude Code to report its own state (working / waiting for your permission / waiting for input / done). On Windows the upstream mechanism cannot work as written (it is a Unix shell command). Default: FanBox writes a hook file that makes Claude Code call FanBox directly over HTTP, with no shell involved. What you see: the tab dot, the 「轮到你」glow, the chime and the new 指挥台 (session list) react the instant Claude asks for permission, instead of 2–3 s after the screen goes quiet.

Terminal tab strip + 指挥台 (2 or more sessions)

Rows appear only for sessions that need you; Ctrl+Alt+L jumps to the next one. Sessions started by typing claude yourself keep today's heuristics.

Prerequisite on the user's machine: the HTTP hook needs a recent Claude Code. If your installed version rejects it, I switch to the shell-command form, which works when Git Bash is installed (Claude Code on Windows requires Git for Windows anyway). Your test C1–C3 decides which one ships.

Options: (a) default · (b) ship with hooks off on Windows (everything behaves exactly like 2.13.0; 指挥台 and 本回合 attribution stay approximate).

D3 · Codex: best effort

Codex reports through a "notify program" that must be a real executable. Default: a small Node script run by node.exe, only if node.exe is found and the argument survives Codex's Windows launcher byte-exact (your test C9 proves it). Otherwise Codex launches without it and keeps the old busy/idle heuristics. Codex is never launched with a flag that could make it fail to start.

Options: (a) default · (b) skip Codex hooks this release.

2 · What Windows users will notice in 2.16.1

  • Terminal stays responsive while thumbnails or big directory scans run (2.14: the backend runs in its own process). Task Manager shows a fanbox-server child under FanBox; if it dies it restarts by itself.
  • Markdown with many photos no longer freezes the editor (thumbnails in the editor; exports still use full-resolution images).
  • 指挥台 and precise agent status (D2), 本回合 panel merging inbox / replay / snapshots, single-file restore, send selected diff lines to the agent, md diff in reader view, image before/after slider.
  • Quit confirmation only when an agent is actually working; stay-awake likewise (D5).
  • Snapshot storage is visible and cleanable (usage per project, 清理此项目存档, 清理失效仓库). On Windows sizes are computed by summing file lengths, so they read slightly smaller than macOS's block counts.
  • Security: Markdown is sanitized before rendering (upstream's version of the fix first shipped in this fork), a page CSP, and every write action in the desktop app now needs a per-launch token, so another local process cannot drive FanBox's file operations.
  • Smaller sidebar (「更多…」menu), rewritten first-run guide, .jsonl previews, skill-collection repos recognized, ⇧Tab full-text search.
  • Upgrade path: installed or portable 2.13.0 shows 「下载更新」for 2.16.1, and 2.16.1 will do the same for later versions (D1: no auto-install on Windows).

3 · Your part: tests on the Windows PC

These are the cases only a physical Windows machine can answer. Same setup as v2.13.0: isolated profile (USERPROFILE/APPDATA/LOCALAPPDATA redirected), VS Build Tools + Spectre libs, Node, Git for Windows. Please record: candidate OID, Windows build, Node / Git / PowerShell / Claude Code / Codex versions, and whether Git Bash is installed (it changes D2). Every item has a pass criterion; a fail or a skipped required case stops the gate. Groups A–F run on the source checkout (Gate C); G runs on the built packages (Gates D/E).

A · Process model
  • A1 Launch from source and later from both packages by double-click in Explorer: Task Manager shows fanbox-server under FanBox; UI loads; no crash in the log.
  • A2 Kill fanbox-server in Task Manager: it comes back within seconds and the app keeps working. Kill it six times in a row: a localized "backend failed to start" dialog, then the app exits with no orphans.
  • A3 Close the window (✕ or Alt+F4) with no agent running: no dialog, no leftover fanbox-server or powershell.exe.
  • A4 Start FanBox from the Start Menu (not from a terminal) with git only on the user PATH: git status works, thumbnails generate, one-click Claude Code starts. (Proves the PATH merge reaches the backend child.)
  • A5 Start a second FanBox: the port-in-use dialog appears after the retry budget; the first instance is unaffected.
B · Token and security
  • B1 In the app: save, rename, Recycle-Bin delete, create file, switch language, save a cron task, 排版 → 导出长图, insert image. All succeed.
  • B2 From an outside PowerShell, POST to http://127.0.0.1:4567/api/trash with a JSON body: 403 bad token.
  • B3 Malformed JSON to any POST endpoint: 400; nothing in the profile is touched.
  • B4 Open the XSS fixture Markdown in Read, editor, 排版, WeChat bubble and version history: inert. A legitimate document with C:\… images and a <a target="_blank"> renders images and keeps the target.
  • B5 HTML preview: scripts run inside the iframe, cannot reach /api; window.open to an http URL goes to the system browser; a file: link does nothing.
  • B6 Plant git.exe in a project, open an image's before/after view and a diff: the planted binary never runs.
C · Hooks (D2, D3)
  • C1 One-click 「启动 Claude Code」: the typed command carries --settings "C:\Users\…\.fanbox\hooks\claude-settings.json" (absolute, quoted); Claude starts cleanly. Repeat with default shell cmd.exe (FANBOX_SHELL) and PowerShell.
  • C2 The hooks file contains no token; inside the tab, curl.exe "$env:FANBOX_CTL/terminals" -H "x-fanbox-token: $env:FANBOX_CTL_TOKEN" shows hooked:true after the first prompt.
  • C3 Trigger a permission request: tab dot + glow + chime the instant the prompt appears; 指挥台 lists the session under 等你确认; approve; at turn end it shows 刚完成 and clears on focus.
  • C4 Let Claude edit a file: 本回合 groups it under the terminal name with the agent icon; 查看改动 and 还原此文件 work; a newly created file goes to the Recycle Bin with 回收站 wording.
  • C5 Stay-awake dot is green while the agent works and turns off within seconds once it waits at the prompt.
  • C6 Quit mid-turn: dialog names the agent; cancel keeps everything. Quit while idle at the prompt: no dialog.
  • C7 Resume a session from the list: the command still carries the hooks flag.
  • C8 A cron task and an AI 整理 run also become hooked.
  • C9 Codex: if enabled, a completed turn shows hooked:true and the argv-dump shim shows the notify argument byte-exact. If disabled, Codex starts bare and the old heuristics still work.
  • C10 With HTTP_PROXY set in the user environment, hook events still arrive.
  • C11 A manually typed claude behaves as before (heuristics, hooked:false).

6.4 · Load-bearing constraints

  • Golden rule. macOS/Linux branches and literals stay byte-identical to master. Windows behavior only inside PLATFORM === 'win32' / IS_WIN / isWindows() / state.sep === '\\' arms, Windows-only helpers, or new dictionary keys. Accepted shared-text edits this round, each classified in verify.js and listed in the changelog: (1) autoUpdater.on('error', …); (2) inert-<template> semanticSig(); (3) platform-ternary fsp.rm retry options; (4) optional third parameter on run(). Anything else shared is a scope change.
  • server.js: Node built-ins only, never requires electron/; win-port-helpers.js requires only path; parseWinProxyServer twins in sync (upstream did not touch them).
  • Never build cmd/PowerShell strings from user data; argv spawning; gitExe() + winSpawnEnv() for every git spawn; Windows busy tri-state keeps null = busy; sandboxed preload keeps using sendSync IPC.
  • The hooks files never contain the token; it lives only in process env and additionalArguments. Hook flags are appended only if the file exists (a missing --settings file makes claude exit).
  • New UI strings are Chinese in app.js with dictionary entries; Windows wording via FANBOX_UI_MAC, fileManagerName(), trashName(), modKey().
