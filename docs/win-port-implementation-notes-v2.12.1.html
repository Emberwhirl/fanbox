Windows Port v2.12.1 — Implementation Notes

Live log for docs/win-port-implementation-plan-v2.12.1.html. Defaults from the plan used unless listed under Deviations. Branch: dev. Implemented 2026-07-30.

Status: COMPLETE for theoretical deliverability on Windows 10/11 x64, after a second review round (2026-07-30) that audited the remediation itself — see Round 2. Physical Windows manual matrix (§6) remains the merge gate for dev → windows and was not run in this environment.

Round 2 — review of the remediation (2026-07-30)

Four parallel reviews (server/main correctness, frontend/WeChat correctness, golden-rule parity, security) over the uncommitted working tree. Everything below was found in the remediation, verified with a concrete failure scenario, and fixed in the same working tree.

Security

  • Preview dot-directory filter bypassed by NTFS 8.3 short names. server.js previewPathAllowed tested segment names for a leading ., but the system volume generates .ssh→SSH~1, .claude→CLAUDE~1. Preview iframes run allow-same-origin against the preview port, so a malicious previewed HTML could fetch('/fs/C:/Users/<u>/SSH~1/id_rsa') and exfiltrate it. Fix: fs.realpathSync.native expands short names (and resolves junctions, closing mklink /J too) before the segment check; if realpath fails and the path contains ~n, refuse. Both reviewers found this independently. Regression suite: experiments/winport-parity-202607/preview-guard.test.js (16 cases).
  • Bare command names resolve against the current directory on Windows. libuv searches cwd before PATH; /api/git, snapshots and the release wizard all pass a user-controlled directory as cwd, so a planted git.exe in a browsed repo executes as the user on click. Fix: winSpawnEnv() sets NoDefaultCurrentDirectoryInExePath for FanBox's own spawns only (user PTYs keep native Windows semantics); system binaries (powershell/cmd/explorer/taskkill) now use absolute System32 paths in server.js, main.js, driver.js, env.js.
  • PowerShell quoting. shQuote (app.js, path insertion) and shellQuote (release wizard) escaped ' the POSIX way ('\'') while the Windows PTY is PowerShell ('') — a filename containing ' pushed the tail outside the quotes. Both platform-forked. Release step chaining also moved off && (absent in PS 5.1) to right-folded if($?){…}, preserving stop-on-failure.

Correctness

  • Every relative markdown image 404'd on Windows — the fallback resolver counted the drive twice (C:/C:/Users/…), and it had been switched to fsUrl() (preview origin), which on macOS newly 403'd any image outside $HOME. Restored master's main-origin /fs emit on POSIX (byte-identical) with a win-only leading slash.
  • FFMPEG_PATH demoted below the PATH walk → a codec-stripped ffmpeg.exe on PATH beat the user's explicit build. Restored to highest priority.
  • Multi-frame GIF/HEIC: magick writes cache-0.png, cache-1.png… so the awaited cacheFile never existed. Added -delete 1--1 (not src+'[0]', which would misparse filenames containing brackets).
  • trashPath dispatched directory junctions to DeleteFile via lstat (reports the link, not the target) → recycling always failed. Now re-checks with stat on win.
  • termVerify treated rooted-but-driveless paths (\foo, Git-Bash /c/Users/…) as relative; now uses path.isAbsolute. Dead isAbsPathCand removed, as were parseEnvBlock and an unused os require.

Golden-rule & i18n regressions introduced by the remediation

  • macOS Chinese UI had drifted: the preview toolbar and artifact card used master's 「在访达显示」 / 「在访达打开」, not 「在 Finder 显示」 (only the context menu uses the latter). Restored; the non-darwin arms use the spaced labels that actually have dict keys — the no-space variants 「在资源管理器显示」 matched nothing, so EN-mode Windows saw Chinese.
  • Backslash treated as a separator on POSIX in isRel, basename, and the scrollback link scanner — a macOS file legally named a\b.md got the wrong basename. Guarded on isWindows(); POSIX expressions restored to master text.
  • Linux drift reverted per D8: clip:file (had gained a writeText success path), the quit-menu label, and the 'macOS only' error string.
  • Disk-panel max restored to master's expression; snapResolveProject's trailing-separator strip platform-split to match its snapshot() sibling.
  • i18n gaps closed: full-sentence key for the Windows WeChat sleep tip (the previous fragment key could never match a text node), rules for the Windows terminal-count state lines and for the launch-failure toasts, and “this Mac” EN values now platform-conditional (computer/PC) like 「离开电脑」 already was.
  • Two macOS-only surfaces still reachable on Windows per the plan's own elimination rule: the AI-organize brief instructed agents to move deletions to ~/.Trash/, and the release command attached dist/*.dmg. Both platform-forked.

Known, accepted, not fixed

  • driver.js stripAnsi is one shared regex spelled \x1b where master has a raw ESC byte — semantically identical, textual drift only.
  • The in-app updater runs the downloaded NSIS installer with no signature or checksum verification (macOS leans on Gatekeeper; the Windows build is unsigned). TLS to github.com is the only integrity control. Worth a published SHA-256 or code signing before wide distribution — a release-process change, deliberately out of scope here.
  • UNC paths (\\server\share) in the markdown-image fallback lose their prefix; no Windows UNC support was claimed for v2.12.1.

Deviations

  • Update check structure (§4 main.js:334). Plan suggested fully separate fetchLatestReleaseWin + literal master REL_PAGE. Kept shared REL_REPO = IS_WIN ? 'Emberwhirl/fanbox' : 'alchaincyf/fanbox' with IS_WIN-guarded asset candidates / no-asset dialog. Conservative rationale: behavior matches the plan (macOS still hits upstream; Windows only toasts when a win .exe asset exists); avoids a large dual-copy of the download loop that would drift.
  • Screenshot watcher (§4 main.js:171). Plan wanted master body pasted for POSIX. Kept multi-dir screenshotDirs() + shared onShotFile, with SHOT_NAME_RE split (POSIX = master patterns; win adds Snipaste/屏幕截图). macOS still resolves the single defaults/Desktop path; Linux still skipped.
  • Golden-rule verify.js. Heuristic line scan (not full AST). Flags “non-obvious” additions for human review; does not hard-fail CI. Preserved under experiments/winport-parity-202607/ per repo convention.
  • env.js POSIX dump. Restored master inlined env parse loop on POSIX; parseEnvLines retained for the Windows Base64 dump path (plan allowed this).
