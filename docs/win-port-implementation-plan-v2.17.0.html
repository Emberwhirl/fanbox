1 · Decisions you are most likely to tweak

Each block names the default I will implement unless you say otherwise. Everything here changes what a Windows user sees or what leaves their machine.

D1

A quota line under Claude Code in FanBox-launched sessions

The headline of 2.17.0 is a "status-line bridge". When FanBox starts Claude Code (one-click, resume, cron, AI 整理), it adds a status line to the settings file FanBox already passes with --settings. Claude Code hands that status line its live 5-hour and weekly quota. The bridge sends those two numbers to FanBox's usage panel, which then updates within seconds instead of polling the official API once a minute. It also prints them under the prompt.

2.16.1 today
● Updated src/app.ts
> _
? for shortcuts
2.17.0 default
● Updated src/app.ts
> _
5h 23% · 周 41%

Things to know before choosing:

  • Once any status line is configured, Claude Code hides most footer hints (esc to interrupt, ? for shortcuts). That is Claude Code's behavior, and macOS users get the same trade-off from upstream.
  • The numbers only exist for Claude Pro and Max plans, and only after the first reply in a session. For other users the bridge prints nothing.
  • Your own ~/.claude/settings.json is never written. If you later add your own statusLine, the bridge runs it and shows its output instead of the quota text.
  • A claude you type yourself is unaffected. The change starts with Claude sessions launched after the upgrade.
  • On Windows this needs Git Bash, because Claude Code runs status lines through Git Bash (PowerShell only when Git Bash is missing). Without Git Bash, FanBox leaves the status line out and keeps polling, exactly as 2.16.1 does.
  • Upstream's Windows command string cannot be used. Under Git Bash it would launch a second full FanBox window on every status refresh (details in 6.4).
  • (a)
    Ship the bridge, with a Windows-correct command default
    Same feature as macOS. Requires Git Bash, falls back silently without it.
  • (b)
    Leave it out on Windows
    Claude Code looks exactly as in 2.16.1. The panel's Claude quota comes from the official API every 60 s (it shows 官方数据 instead of CLI实时回传).

D3

Codex quota from the official endpoint (a new network call)

Until now the Codex numbers came only from Codex's own session logs on disk. 2.17.0 also asks chatgpt.com directly, using the Codex login in %USERPROFILE%\.codex\auth.json. The token goes to curl.exe through stdin only, so it never shows in a process list or a log. In return you get your plan name, correct window names (a Pro weekly limit was mislabeled as 5h before), and Codex's limit-reset credits.

2 · What Windows users will notice in 2.17.0

  • Richer Agent 用量 panel. Each agent expands into a token breakdown (uncached input, cache read, cache write, output, reasoning) for the last 5 hours, today and the last 7 days, with an input cache hit rate. Codex shows plan, correct window names and reset credits (D3).
  • Failures keep the last numbers. A failed refresh keeps the last good values and says why, then retries with backoff (30 s growing to 10 min) instead of showing 0%.
  • Live Claude quota in FanBox-launched sessions, plus the quota line under the prompt (D1, D2).
  • No freeze on large log folders. Token counting moved to a background thread and reads only what changed since the last pass.
  • Smoother while an agent writes many files. Repeat notifications for the same file are merged, the queue is capped, and the file list refreshes at most every 0.75 s. Card highlights no longer force a re-layout on every write, so typing in a terminal stays responsive during a burst.
  • Clearer update failures with a download-page button (D5).
  • A small fix: switching folders while the list is refreshing no longer shows the previous folder's files.
  • After upgrading: restart any running Claude Code session to get the quota line. Upstream's release note says the same.

6.4 · The status-line bridge on Windows

Facts it rests on (Claude Code status-line docs, checked today): on Windows the command runs through Git Bash when installed, otherwise PowerShell; Git Bash eats unquoted backslashes, so paths must use forward slashes; status lines have no exec form and no shell field (hooks do). The script runs on events (session start, each new assistant message, mode changes), debounced at 300 ms, and an in-flight run is cancelled by the next.

Command

ELECTRON_RUN_AS_NODE=1 'C:/Users/u/AppData/Local/Programs/FanBox/FanBox.exe' 'C:/Users/u/.fanbox/hooks/claude-statusline.cjs'
  • Built by a pure helper winStatusLineCommand(execPath, scriptPath) in win-port-helpers.js: backslashes to forward slashes, each path in single quotes. Returns null if either path contains ', so no status line is written; spaces, $, backticks and CJK are safe inside single quotes.
  • Emitted only when winGitBash() finds bash, in Claude Code's own order: CLAUDE_CODE_GIT_BASH_PATH (from the merged registry environment the PTYs inherit), then git.exe via the existing PATH walk mapped to <git root>\bin\bash.exe (handles cmd\, bin\, mingw64\bin\), then %ProgramFiles%\Git\bin\bash.exe.
  • If detection disagrees with Claude Code and PowerShell runs the line, it fails with "term not recognized": the status line is blank and nothing is launched. The failure mode is harmless by construction.
  • claudeHttpHookSettings(PORT, { statusLine }) gains an optional second argument; the Windows branch copies the bridge script from the app (works from app.asar) before writing the file. The file stays token-free.
  • Portable build: process.execPath is the unpacked copy in %TEMP%, valid while FanBox runs; the file is rewritten at each launch. Never PORTABLE_EXECUTABLE_FILE, which would re-extract on every refresh.
  • ELECTRON_RUN_AS_NODE already works in this build (the WeChat driver and Codex launch use it).
