3 · Deviations

Places where the work had to depart from the plan. In each case the conservative option was taken.

Dev-1 · Two older shared rewrites in the update code are kept

Plan: goal 3 says macOS/Linux code is byte-identical to master except the shared edits in the 6.7 ledger.

Found: the 2.16.1 port had already rewritten two shared spots that the ledger does not list: the tail of checkUpdate (if (newer && winAssetOk), with the macOS dialog moved into an else) and update:download (split into updateAssetCandidates plus a candidate loop). macOS behavior is unchanged, but the text differs from master.

Chosen: keep them as shipped in 2.16.1. That code has passed the Windows matrix twice, while making it byte-identical would mean a new parallel Windows handler that has never been tested. Plan 6.5 only requires upstream's fetch function and failure dialog to be verbatim, and both are. The ledger in these notes lists the two spots.

Dev-2 · Campaign contract tests are split into separate files

Plan: 6.8 names a single contract.test.js.

Chosen: contract-bridge.test.js (D1, D2) and contract-i18n.test.js (D4), so the two parallel agents never edited the same file. Both run in one command: node --test experiments/win-v2170-usage-202610/contract-*.test.js. A real-browser English check, ui-usage-en.cjs, was added on top of the Node test the plan asked for.

Dev-3 · Lowercase period labels in the sidebar trio

Plan: D4 lists 近5h · 今日 · 近7天 as "Last 5h · Today · Last 7 days".

Found: 近5h → last 5h and 今日 → today already exist as dictionary keys from earlier releases, and the sidebar trio (110 last 5h) renders through them.

Chosen: the existing keys are unchanged, so text that already shipped stays the same, and the new bare 近7天 key reads last 7 days to match them. The new token-breakdown headings use the D4 capitalized form through a rule: Last 5h · 110 token, Today · …, Last 7 days · ….

Dev-4 · A Chinese file name that matches a dictionary key is translated in English mode (accepted)

Found by review: the file list (.fname) is not excluded from translation. In English mode, a folder named exactly 输出 displays as "Output". The same was already true for existing keys such as 图片, 文档, 桌面 and 下载. It is display only; opening the folder still works.

Chosen: no change this round. The fix is to add .fname to the skip list in shared public/i18n.js, which would also change English-mode behavior on macOS. Dropping the key is no fix either: the English panel would then show a Chinese row. Worth raising upstream.

Dev-5 · Three review follow-ups go slightly beyond the plan's wording

Language fallback (D2). The plan's fallback was "the system language". In the bridge, which runs as Electron-as-Node, Intl reports the Windows regional format. The UI follows Chromium's display language instead, so a user with an English display language and a Chinese regional format, who never touched the toggle, would get 周 under an English UI. Windows PTYs now carry FANBOX_LANG = uiLang(). The bridge's order is config.lang (read live), then FANBOX_LANG, then Intl. POSIX PTY env is unchanged.

Git Bash lookup (6.4). Claude Code also accepts CLAUDE_CODE_GIT_BASH_PATH from the env block of its own settings.json. Without reading it, FanBox would silently leave out the quota line even though Claude Code would find bash. writeHookFiles now reads that file, read-only, when the process env lacks the variable.

curl (6.2). The plan's winFindExe('curl') expands PATHEXT, so a curl.cmd earlier on PATH would win, fail with EINVAL, and receive the token on stdin. The lookup is now the exact name winFindExe('curl.exe'), still PATH first and System32 second.

5 · Windows handoff

The candidate is only on this machine, and dev stays private, so it is not pushed. It travels to the Windows PC as a git bundle. Do not start from windows (still 2.16.1) or master (upstream, macOS).

  1. Move the code. Copy the bundle to the PC. Create it with git bundle create fanbox-dev-v2.17.0.bundle dev; it is self-contained. Then either:
    • in an existing clone: git fetch <path>\fanbox-dev-v2.17.0.bundle dev:dev then git checkout dev, or
    • fresh: git clone -b dev <path>\fanbox-dev-v2.17.0.bundle fanbox.
    Check that git log --oneline -2 shows the notes commit on top of fb5cf7b.
  2. Build. Windows 11 with Git for Windows, Node 22+, and VS Build Tools with the Spectre-mitigated libraries. In the checkout: npm install, then npm run rebuild (unset NoDefaultCurrentDirectoryInExePath in that shell if GetCommitHash.bat fails).
  3. Quick checks. npm test (expect 14/14; on Windows the bridge test exercises the Git Bash path). Then node --test experiments\win-v2170-usage-202610\contract-bridge.test.js experiments\win-v2170-usage-202610\contract-i18n.test.js.
  4. Harness setup. playwright-core goes outside the repo: mkdir E:\pw; cd E:\pw; npm init -y; npm i playwright-core. In PowerShell, from the checkout:
    • $env:NODE_PATH = "E:\pw\node_modules";
    • $env:FANBOX_V2170_BASE = "E:\fanbox-v2170" (short, writable, not inside OneDrive);
    • Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue.
  5. Automated cases, in this order (leave the FanBox window visible during U6 and W):
node experiments\win-v2170-usage-202610\playwright-electron.js --dry
node experiments\win-v2170-usage-202610\playwright-electron.js --only S1,S5,S6
node experiments\win-v2170-usage-202610\playwright-electron.js --only UF,R1,X1
node experiments\win-v2170-usage-202610\playwright-electron.js --only W
node experiments\win-v2170-usage-202610\playwright-electron.js --only U6
node experiments\win-v2170-usage-202610\playwright-electron.js --only S2 --soak 10
  1. Manual cases: S2 with real Claude Code, S3, S4, U1, U3, U4, W3, X1b. Start the isolated profile with node experiments\win-v2170-usage-202610\playwright-electron.js --launch, sign in to Claude Code (Pro/Max for S1/S2) and Codex there, and follow the steps the script prints (also in the campaign README).
  2. Record the results in the table at the end of experiments/win-v2170-usage-202610/README.md: candidate commit, Windows build, Node/Git/Claude Code/Codex versions. Evidence lands in %FANBOX_V2170_BASE%\evidence\<timestamp>\. A failed or skipped required case stops the gate. --dry is only a sanity check.
  3. Afterwards: --clean removes the fake homes. W4 sends one small file to the Recycle Bin.

Then Phases 4 and 5: build with npm run dist:win on the PC (G1–G3), then tag and publish (R2). Each needs your explicit go-ahead. Fast-forwarding windows, pushing and tagging can be done here on request.
