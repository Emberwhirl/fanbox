1. Choices you are most likely to tweak

Start here. Each choice explains the visible outcome, the recommended default, and what changing it would cost.

D1 · CLAUDE QUOTA LINE

Show live quota for sessions launched by FanBox

Keep the new bridge enabled when Git Bash is available. Relay the quota to the usage panel while preserving the user’s own status-line output.

With no custom line, show compact 5h 23% · 7d 42% in English; use the existing Chinese wording in Chinese mode. Starting a new Claude session enables the bridge. A manually typed claude remains an ordinary session.

Alternative: omit the injected status line and use API data only. Less CLI integration, but live quota may be less available. Existing dev already implements the bridge; actual Claude behavior still needs a Windows run.

D2 · FALLBACK EXPERIENCE

Explain missing live data without interrupting work

Keep launching the agent if the bridge cannot be prepared. Show a small, localizable explanation in the usage panel, with the available data source.

Use wording such as “Live quota unavailable; using official API data” when that source works. Give a specific reason only when known. A missing Git Bash must not break the HTTP hooks or Codex notifications.

Current gap: dev silently omits the bridge when Git Bash is missing or a path contains an apostrophe. Recommend supporting apostrophes through correct Bash quoting, plus a nonmodal explanation for real setup failures. You can retain silent fallback for a smaller release.

D3 · USAGE PANEL

Keep the new detail, make its meaning clear

Keep collapsible token details for both agents, including cache reads/writes and reasoning where recorded. Preserve expanded sections during refresh.

Label official quota, live CLI quota, and local session totals distinctly. Keep the 5-hour, today, and rolling 7-day local views. Show expired quota as “Awaiting update”; retain stale successful values with their age and failure reason.

Alternative: simplify the default panel further, keeping the breakdown one click away. Do not estimate account bills, missing reasoning, reset-card expiry, or reset-card history. Reset cards show held and currently applicable counts only when returned.

D4 · UPDATES

Retain download-and-run updates for this release

Check Emberwhirl/fanbox releases and offer “Download update.” Keep the installer and portable EXE. Add upstream’s timeouts, useful error reasons, and “Open download page” fallback.

Never offer the macOS upstream release as a Windows upgrade. Keep requiring both exact Windows asset names before offering the new version.

Alternative: implement automatic Windows installation. That is a separate product change requiring installer/portable policies, update metadata, signing decisions, restart behavior, and recovery tests. The upstream macOS auto-updater does not establish Windows readiness.

D5 · INSTALLATION & DATA

Keep installer and portable options

Ship FanBox-2.17.0-win-x64.exe and FanBox-2.17.0-win-x64-portable.exe. Preserve existing user settings on upgrade and uninstall.

Verify both packages from paths with spaces and Chinese characters, and portable launch from another drive. Explain that the current portable package still uses the normal user profile for settings and history.

Alternative: a self-contained portable profile next to the EXE. That needs deliberate migration, writable-location rules, and coexistence tests; defer unless carrying settings between PCs is a priority. Signing is optional scope to decide before release; the 2.16.1 notes record unsigned packages.

D6 · LANGUAGE & WINDOWS CONTROLS

Keep the Windows conventions already established

Retain Chinese/English switching, Windows captions, Ctrl shortcuts, Recycle Bin wording, and Ctrl+Alt+M for terminal maximize.

Translate the new quota details, dynamic window labels, errors, tooltips, and native update dialog. The terminal quota line should follow FanBox’s selected language, including on a fresh profile.

Review point: the existing dictionary translates the exact string “输出” globally. A file or folder with that name may display as “Output” in English. Recommend protecting user filenames/content from UI translation and adding a regression case.

D7 · LIVE FILE CHANGES

Favor responsive typing and a list that catches up

Adopt upstream’s batching and throttling first. Keep folder heat and change summaries, while allowing the complete file list to update after a short delay.

Proposed acceptance: after a 2,000-file burst over 8 seconds, the final file appears within 2 seconds of the burst ending; another terminal stays usable. Three seconds is a warning to investigate.

Alternative: tune for faster list updates after measuring Windows. Reducing delays prematurely can restore the stalls this release fixes. Change tracking is a live summary, not an exhaustive filesystem audit.

D8 · SCOPE & RELEASE

Finish the existing candidate before broadening support

Use the fetched dev candidate as the starting point. Keep the release target at Windows 11 x64; retain previously working editor, snapshots, agent control, and WeChat functionality.

Develop against your server’s origin/dev. Publish the validated result through GitHub’s windows branch and versioned release. Keep GitHub master as the upstream mirror.

Deferred scope: Windows 10, ARM64, WSL-specific integration, automatic installation, and a new settings system. Existing ARM64 build switches are not evidence of supported ARM64 binaries.

The fetched dev is already a candidate.

origin/dev contains the upstream merge, Windows bridge, translations, regression harness, and Linux handoff notes. The remaining work is targeted fixes and validation, not a fresh port. The original plan and notes remain untouched; this review adds a current plan.
